# Agents

## Purpose
Top-level Ansible playbooks that provision monitoring and infrastructure services (Grafana, Loki, Prometheus, Redis).

## Working agreements
- Each playbook targets a specific host group and composes roles from `../roles/`.
- Keep playbooks minimal; put logic in roles, not here.
- Ensure host groups match the inventory generated by DeployEx Mix tasks.
- `mimir_db.yaml` provisions a standalone Mimir metrics node — opt-in like `redis.yaml`,
  not referenced by any other setup playbook. It is **not** wired into a `--no-mimir`
  toggle or an `.eex`-conditional `grafana_alloy` role line on `grafana_ui.yaml`,
  `loki_log_aggregator.yaml`, or `prometheus_db.yaml`: MEASURED on this line,
  `Mix.Tasks.Ansible.Build` has no per-file `.eex` render path for
  `priv/ansible/setup/*.yaml` beyond `ansible.cfg.eex`, the hosts inventory template,
  `group_vars/all.yaml.eex`, and the per-app `app_playbook.yaml.eex`/
  `app_setup_playbook.yaml.eex` pair — `ensure_ansible_directory_exists/3` seeds this
  directory with a raw `File.cp_r!`, so a `.yaml.eex` file here would sit un-rendered.
  A consumer that wants those three node types to also push their own `node_exporter`
  metrics to Mimir must add `- grafana_alloy` to the relevant playbook's role list by
  hand for now.
